# 长任务纪律

用途：当任务会跨很多轮、很多次实验，或对话长度会超出一次能装下的上下文时，读这一篇。
准备接手别人（或过去的自己）开了一半的任务时，也先读它。

要防的失败不是工具层面的，是**判定漂移**。长任务里三件事会稳定地出错，而且每一次的代价
都在发生时看不见：

1. **重新推导已经证过的结论**。轮次花在重新发现一个早先已经确立、后来却丢掉的边界或机制上。
2. **重走已经排除的路线**。排除是真的，但排除的理由被忘了，于是这条路线看起来又有希望了。
3. **一个错误结论继续掌舵**。早期的错误归因被写进脑内模型，此后很长时间里安静地砍掉好选项、
   或者撑着坏选项。

三个同源：**结论活在上下文里，而不是活在磁盘上**。

## 维护活记录，而不是日志

维护一个工件——一个文件——它是这个任务的权威状态。学到东西就更新，不要等到最后。
重要的不是体量，是**每一条以后都能拿来做决定**。

保留这些段落：

| 段落 | 内容 | 作用 |
|---|---|---|
| **运行规则** | 每次运行都必须成立的事（怎么装、怎么起、怎么抓取） | 防止重复犯机械性错误 |
| **已确认事实** | 每条都带证明它的那次运行 | 其余一切建立其上 |
| **被推翻的结论** | 原本信什么、为什么错、被什么取代 | 挡住死想法复活 |
| **死路** | 已排除，附证据 | 单项最省时间的一段 |
| **开放问题** | 还不知道什么 | 让下一步保持诚实 |
| **环境** | 设备、端口、工具路径、凭据位置 | 免去重新发现 |

两条规则让这个文件值得存在：

- **每条断言都带证据。** "脚本拒绝这个输入"必须附上显示这一点的那次运行，包含确切的报错文本。
  没有出处的断言，就是后来采纳一个错误结论的方式。
- **推翻是一等条目。** 发现早先结论错了，就把**错的结论和错的原因一起记下来**。
  删掉错误，等于丢掉这次学到的最有价值的东西。

## 给自己的结论分级

每条非显然的陈述都标上强度，并且**绝不允许弱标签继承强标签的权威**：

| 档位 | 含义 | 能否据以决策 |
|---|---|---|
| **observed** | 复现过，有确切命令与输出 | 能 |
| **inferred** | 由观测推出，但中间步骤是推理的 | 暂定可以 |
| **hypothesis** | 看起来合理，未测 | 只能作为待测项 |
| **refuted** | 测过，是假的 | 永远不能，只作为警告保留 |

长任务里的大部分损伤，来自 hypothesis 仅仅因为被反复重复，就向上漂成"事实"。当你发现自己把
某件事称为"已确立"，去记录里查它的档位。如果不是 observed，就去观测它，或者重新贴标签。

## 每个脚本用令牌回答，而不是用散文

长任务是一条决策链，每个决策读上一步的**结果**。当那个结果是人读的散文时，读取这一步就变成了
解释——而解释正是错误结论潜入的地方，且不附带任何错误信息。本仓库已经为此付过一次代价：
一次只看日志的判定得出"某模块从未运行"，而它实际运行了九次。

所以本套件的脚本以机器可判的答案结尾，退出码承载同样的含义：

- **最后一行 `RESULT=<token>`**，取自一个小而封闭的词汇表（`OK`、`DRIFT`、`OVER_BUDGET`、
  `FAIL`、`SKIP`…）。令牌是答案，它之前的一切是给人看的证据。
- **退出码含义固定**：`0` 令牌指向成功，`1` 是一个真实的否定发现，`2` 脚本无法履职
  （用法错误、输入不可读、缺依赖）。**`2` 永远不是关于目标的发现**——这个区分就是全部意义所在，
  把它混掉，等于把一个坏掉的工具变成目标本身的属性。
- **计数也是令牌**（`FOUND=0`、`TESTS=113`、`drift_count=0`），让"什么都没发生"成为一个
  可以分支的值，而不是一个你得自己注意到的空缺。

对读的人来说规则是另一半：**先看令牌和退出码，再看散文。** 两者矛盾时，令牌是脚本作者定义的，
散文是他那天脑子里想的。

## 贯穿整个任务的单变量纪律

错误**且持久**的结论，最常见的来源是复合实验：改两处、失败一次、编一个解释。因为失败是真的，
解释就感觉像是挣来的。

要执行的后果：

- 一条路线即将被放弃时，**重读它当初为什么被放弃**。如果当时的证据是复合的，这次放弃就还不成立——
  先用单变量重跑一遍再写死。
- 在流程里留一个语义对照：**零改动**的构建，走同一条安装与启动路径。对照失败，
  你此后测到的任何东西都没有意义。

## 在自然检查点防漂移

这些做起来很便宜，而且只在能改变决定的时候做——不要当成仪式。

- **开始一个新实验之前**：读被推翻结论段和死路段。如果你的计划出现在那里，停下，读为什么。
- **宣布进展之前**：问用户可见的结果此刻是什么。内部信号变好不是进展。重述真实目标。
- **任何意外之后**：立刻带证据写下来，赶在你形成理论之前。事后写的理论和观测难以区分。
- **上下文感觉变长时**：优先写记录，而不是重读对话。记录是能活下来的那个，对话是会被截断的那个。
- **恢复任务时**：先读记录，把不在记录里的一切当作未知，哪怕它感觉眼熟。

## 最昂贵的漂移：在交付物永远不会见到的环境里解决问题

这个领域里有一种漂移比其他所有加起来都贵，因为它产出一个看起来像成功、但不是成功的结果。

**仅运行时的结果容易拿到，也容易被误认为成品。**

改一个数据文件、挂一个活进程、拦一个域名、开一个代理——每一个都能让程序**在你动手的那台机器上**
表现正确，而且不需要重新打包。它常常是通往一个可见胜利的最快路径。它也常常**根本不是交付物**，
因为需求从来不是"让它在这里能用"。

决定这件事的约束轴——每一条都对着原始需求核一遍，并且在动手前把答案写成一句可检验的话：

| 轴 | 问题 | 为什么它会安静地让工作作废 |
|---|---|---|
| **权限** | 是否必须**免提权**运行？ | 只在提权下成立的结果，根本交不到普通用户手里 |
| **修改形态** | 必须是**重新构建的成品**，还是运行期插桩的结果也可接受？ | 插桩与数据修改不会随成品一起交付 |
| **ABI / 设备类别** | 哪个 ABI、哪个设备族？ | 只在模拟器或只在 x86 上的结果，不是物理 ARM 设备的证据 |
| **网络** | 是否必须在**联网**下工作？ | 依赖离线或依赖本机代理的做法，一进入正常使用就失效 |
| **持久化** | 是否必须扛住重启、升级、全新安装？ | 内存态和会话内状态会蒸发 |
| **分发** | **交出去的那个文件**是否必须自包含？ | 任何需要在机器上另装辅助物的方案，都不是可交付成品 |

**检查点问句，与上面的漂移检查在同一时刻问：**

> *如果我现在就把手头这份东西交出去，它满足我一开始写下的那句约束吗？*

如果答案是"不"，你在一个**组件**上取得了真实进展，值得这样说明——但它不是任务。
不要让"它能跑"顶替"它在约束下能跑"。

**不要过度声称，而是这样拆分结果：**

1. **约束内可达的部分**，以及它推进到哪一步。
2. **无约束的变通做法**（需要提权 / 需要宿主 / 需要代理），明确写成有意选择的退路，
   并把它的前提条件对读者讲清楚。

有特权的变通做法是真正有用的——它可能是"能用"和"不能用"之间的差别。它变成问题，
只在它被当成交付物呈现的时候。把它作为退路汇报，把受约束的目标继续挂着，并直说手里是哪一种。

**同时注意反向情形**：如果约束是"必须是重新构建的成品"，不要让一个能跑的运行时结果悄悄关掉调查。
用它擅长的事——它证明了机制、指出了要改的确切代码或数据——然后把那个发现搬进成品里。
运行时结果是地图，不是目的地。

## 给每个等待设上界

长任务会以不产生任何信息的方式停摆，同时消耗你最宝贵的资源：墙上时间和下一位的耐心。
三个习惯能挡掉几乎全部。

**1. 每条命令都有超时，没有超时本身就是 bug。** 一个没有超时就去调外部命令的辅助脚本可能永远挂着，
而它的表现是"任务停止推进"，不是"这次调用阻塞了"。给每个子进程、每个 HTTP 请求、
每次设备调用显式传超时。超时发生时，结果是**未知**，不是失败——按未知记录，重试前先复查状态。

**2. 预期时长来自测量，不来自猜测。** 超时只有相对于"这个操作本该花多久"才有意义，
因为那才是让"慢"和"挂死"可区分的东西。猜出来的预算要么短到把健康的工作杀掉，
要么长到让停摆看起来像耐心。

所以：**测一次，写下来，再推导上界。**

| 操作类别 | 怎么定上界 |
|---|---|
| 本机工具（编译器、打包器、签名器） | 秒到低分钟级；计时一次，然后设成观测值的约 3–5 倍 |
| 设备 shell 调用 | 秒级——**例外**是重启后的第一次提权调用，它可能弹提示并阻塞 |
| 安装 / 推送大产物 | 分钟级；随体积伸缩，不随目标复杂度伸缩 |
| 程序冷启动到首帧 | 数十秒——**加了壳会更长**，壳会在你的代码跑之前做真活 |
| 需要人或外部服务的步骤 | **原则上无界**——根本不要等 |
| 等待屏幕状态变化 | 既要设上界，**也要采样**（见第 3 点） |

把观测到的时长记进活记录。它们正是那种在上下文丢失后会被痛苦地重新推导的机械事实；
有了它们，后来的超时就是一个可解释的信号，而不是一个谜。

**超出预期窗口这件事本身就是发现。** 它告诉你状态层面的东西——设备卡住了、程序从未到达那个阶段、
动作从未发生——那是一次不同的调查，不是把截止时间往后延。复查状态，而不是延长期限。

**3. 每个等待都有截止时间、有可采样的观测量、有一次实际查看。** "等操作完成"不是计划。
点名观测量、多久采样一次、采多久后放弃、以及超时后你得出什么结论：

```text
等待对象：<观测量>        例如：遮罩消失 / 计数器递增
采样：    <间隔 + 方式>   例如：每 15 秒截屏 + 当前前台组件
放弃于：  <截止>          例如：150 秒
超时结论：<你得出什么>    例如："窗口内未完成"——不是"不可能做到"
```

**用眼睛采样，而不是盲睡。** 当这一步被某个可见的东西闸住——屏幕、对话框、进度指示——
去抓取它并**看一眼**，而不是睡过整个间隔。固定睡眠要么浪费时间，要么量错时刻；
看一眼告诉你实际发生了什么，而连续两帧逐字节相同则告诉你什么都不会再变。
这是避免把轮次花在一个永远不会到来的状态上最便宜的办法。

由此得出三条规则：

- **过期的截止是一次测量，不是一次裁决。** "N 秒后仍未完成"告诉你的是延迟和可靠性，
  它不告诉你这个做法不可能；把它写成不可能，正是一条可行路线被丢弃的方式。
- **有独立工作时，永远不要忙轮询一个长任务。** 起它，去做另一件事，等它落定再收。
  轮询浪费的正是任务已经在花的那份资源。
- **宁可有界地观测，也不要固定睡眠。** 轮询你真正在意的状态并设上限；宁可采样一个能查看的东西，
  也不要赌一个希望正确的时长。

## 保持观察窗口洁净

本篇的每条结论都建立在"我看到的构建就是我做的那个构建"上。这个假设比其他任何一个都更常被
安静地破坏，而被污染的窗口看起来并不像被污染——它看起来像一个结果。

三种发生方式，每一种都产出过自信的错误发现：

- **你观测时别的东西动了目标。** 另一个进程、另一个代理、你自己另一个窗口的工作装上了、
  回退了、恢复了或清空了它。你的截图和日志于是是两个状态的混合物，且两者都不描述。
- **你在看一个陈旧进程。** 程序其实从未重启，于是"改前"和"改后"的抓取来自同一次运行。
- **设备上的产物不是磁盘上的产物。** 一次报告成功的安装，或者因为版本号相同而被跳过的安装，
  留下的还是上一个构建在跑。

护栏，按代价从低到高：

1. **钉住身份，不是文件名。** 给你构建的产物、你打算测试的产物、以及实际装上去的产物分别算哈希——
   文件名什么也证明不了。在观察窗口开始前立刻做，不是几小时前。
2. **有意地开启窗口。** 在一段结论将要依赖的抓取序列之前，声明（对自己或对记录）接下来 N 秒
   只用于这次观测，窗口内不跑别的安装 / 卸载 / 清数据。
3. **给窗口打时间戳。** 记录墙钟起止。它只花一行，却是事后唯一能发现同事、后台任务或你自己
   更早的命令落在窗口内的办法。
4. **宁可一次连续抓取，也不要几段短的。** 重启过的抓取邀请重启过的状态；一段连续序列无法跨越
   一次它自己没做的安装。

当发现窗口被污染时，**正确动作是丢弃它并重抓**，而不是抢救它。重跑花几分钟；错误结论花掉
任务剩下的部分，而且它会从同一批坏证据里被重新推导出来，因为记录说那是 observed。

### 没看过的截图不算证据

这与被污染的窗口是两种不同的失败，而且它能穿过上面每一道护栏活下来。帧是真的、时间戳是诚实的、
哈希是对的——只是没人看过它们。

两种形态，都会产出自信的错误答案：

- **你截了图就往下走了。** 图像存在；结论却是从日志或从补丁本身得出的。
  一串未被审视的帧，在报告里读起来和一串被审视过的完全一样。
- **你看了，但看错了东西。** 每一帧显示的都是别的窗口——上一次安装残留的确认框、系统对话框、
  启动器——而因为帧与帧彼此一致，确信感反而增长。当所有帧共享同一个盲区时，一致不是印证。

护栏：

1. **在信任任何抓取之前，先确认屏幕上是什么。** 一条命令就能定案：查当前前台组件。
   如果组件不是你的包名，这些帧描述的是别的东西。在抓取序列开头做一次、结尾再做一次——
   前台会在序列中途变化。
2. **立刻审视，不要"等会儿"。** 看第一帧、中间一帧、以及任何一个你在意的时刻的帧
   （闪屏本该出现的下一秒、对话框本该弹出的那一刻）。如果你不能用一句话描述一帧显示了什么，
   你就没看过它。
3. **把连续相同的帧当作信号。** 逐字节相同意味着屏幕是静止的。那是一个发现——挂死、
   在等输入的对话框、从未变化的界面——不是一个可以跳过的抓取瑕疵。
4. **在记录里逐帧点名你看到了什么。** 每帧一行。"f03 @2.1s：目标主界面，列表已填充"是证据；
   "抓了 12 帧"是文件清单。
5. **一张看起来干净的屏幕截图，不能证明对话框不存在**，除非你在它本该出现的那一刻连续抓取过。
   采样不是观测：一个出现后又被遮住的模态框可以完全落在两次采样之间，
   而你恰好拍到的每一帧都显示着别的东西。

## 长上下文衰减：同一个错误犯两次

长任务有一种与目标无关的失败模式：**随着工作上下文被填满，已落定的结论失去它们的效力。**
两小时前确立并验证过的东西，到末尾就变成了又一个看起来合理的信念——而从一个卡住的位置
走到"感觉在推进"最便宜的路，就是重试那件已经失败过的事。

症状，如果留意就能认出来：

- 你正要跑一条结果你早先已经记过的命令。
- 你正要重新推导一个就在你自己笔记里的事实（包名、一个偏移、一个版本、哪个改动落了地）。
- 你正要重试一个失败过的做法——而那个失败在你脑子里和这次尝试没有明显联系。
- 你当作扎实的某个结论，其实从未被验证，只是早期被假设、然后一直被重复。
- 你在凭记忆重写任务摘要，而不是读记录。

**解药是一份为任务后半段写的记录，而不是为末尾的某个读者写的。** 保持结构化，
让一次被削弱的上下文读取仍能拿到与决策相关的内容：

```markdown
## 已落定（已验证——不要重新推导）
- <事实>                      [怎么验证的，一句话]
## 已推翻（不要重试——每一条都花过时间）
- <做法> —— 失败，因为 <机制>
## 当前在用的未验证假设
- <假设> —— 当 <条件> 成立时会变成问题
## 下一步，以及它如何被判定
- <一步> —— 成功看起来像 <可观测项>
```

三条起决定作用的规则：

1. **记机制，不只记结果。** "走那个接口会弄坏主界面，因为子请求共享父级加载"能穿过上下文衰减；
   "试了接口那事，不行"不能——而第二种写法会邀请第三次尝试。
2. **在每个检查点、以及开始任何新实验之前重读记录。** 不是等到最后。代价是几秒，
   而它是挡在你和一次循环之间的唯一东西。
3. **同一形态失败两次，说明模型错了，不是参数错了。** 不要跑第三个变体。这与技能里的
   双振出局是同一条规则，而长上下文衰减正是让人违反它的原因。

一个有用的不对称：**重新验证便宜，重新决策不便宜。** 从产物里把一个值读回来只要一秒，
完全可以做。因为忘了结论而重跑整个实验，才是花掉那一轮的东西。

## 交接

一次交接就是记录加三样东西，写给**完全**不记得这个任务的人：

1. **运行规则放最前**——任何不为人知就会安静浪费时间的事。
2. **诚实的当前状态**——包括**没有**达成的部分。乐观的摘要让下一个人付出的代价远大于准确的摘要，
   因为他会在上面继续搭。
3. **下一步最好做什么，以及为什么**——再加上死路，让他们不从那里开始。

有两样东西属于每一次交接，因为它们最难恢复：

- **你搞错了什么**，以及纠正它的证据。
- **你从未真正验证过什么**，直说。"从未确认"比沉默有用。

## 避免反向的失败

纪律本身也会变成负担。也要防这个：

- **不要什么都记。** 只记会改变未来决策、或防止重复犯错的东西。没人看的记录比没有记录更糟，
  因为它看起来像覆盖度。
- **不要把记录当权威。** 它是摘要；环境是真相。记录和一次新观测冲突时，重测——不要为记录辩护。
- **不要让档位钙化。** 一个变得可测的假设应该被测试，而不是被归档。
- **不要让记录的结构支配工作。** 某个段落因为与本次任务无关而空着，就让它空着。
