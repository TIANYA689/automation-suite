# 模拟执行

用途：在无设备、无系统的条件下把单个函数跑起来，用于算法复现与结论验证。

程序步骤见 `emulated-execution-debug` 技能；本页给策略与判据。

## 适用边界

| 适合 | 不适合 |
|---|---|
| 单个函数 / 代码片段 | 需要完整内核语义 |
| 算法复现（加密、哈希、编码） | 需要真实网络交互 |
| 跨架构片段执行 | 需要图形或硬件外设 |
| 绕过 JNI / syscall / libc 依赖 | 需要长时间运行的复杂状态机 |

## 五条原则

1. **原始字节优先**：能裸跑就不解析可执行文件格式。
2. **显式识别上下文依赖**：不假设"没有外部调用"。
3. **大量使用回调**：回调既是环境模拟，也是调试与错误恢复手段。
4. **迭代修复**：每次崩溃是一条信息，不要重写脚本。
5. **最小 trace**：块级优先于指令级；指令级只在很小范围、很短窗口内开启。

## 环境模拟对照

| 类别 | 典型函数 | 模拟策略 |
|---|---|---|
| libc | malloc/free/memcpy/strlen/printf | 宿主语言实现；malloc 用 bump allocator |
| JNI | GetStringUTFChars/FindClass/GetMethodID | 建假函数表，每项写返回桩，hook 桩地址 |
| syscall | read/write/mmap/ioctl | hook 中断事件，按系统调用号分发 |
| C++ runtime | operator new / __cxa_throw | hook 并模拟 |
| 库函数 | 互斥锁 / 动态加载 | hook 后直接返回成功 |

**通用模式**：代码回调命中已知导入地址 → 执行模拟逻辑 → 把 PC 设为返回地址跳过原函数。

## 迭代调试循环

```text
Run → 读回调输出（哪个地址 fault、read/write/fetch）
Diagnose
  fetch 未映射      = 缺代码页
  read/write 未映射 = 缺数据段或指针未初始化
  命中导入桩        = 加模拟 hook
  死循环            = 加执行计数，超阈值停
Fix → 只改一处
Re-run
```

## 常见坑

| 坑 | 处理 |
|---|---|
| 忘记设返回地址 | 函数 ret 时跳到 0；显式写返回地址为哨兵值 |
| 栈未分配 | 必须显式映射栈区并设置栈指针 |
| 字节序搞错 | 大端架构写错会得到"看似合理的垃圾数据"，最难发现 |
| 寄存器未初始化 | 某些代码假设调用者已清零；显式置 0 并记录该假设 |
| 高估可模拟范围 | 一旦需要真实内核语义，停止扩展，改为桩掉或换真机 |
| 把模拟成功当结论正确 | 跑通只说明不崩；正确性必须用已知输入输出对验证 |

## 与静态分析的配合

模拟执行最适合**验证**静态结论，而不是替代它：

```text
静态分析 → "这个函数大概是某种解密"
模拟执行 → 喂入密文，看输出是否为可读明文
输出合理 → 静态结论升级为高置信度
输出不合理 → 参数/密钥/范围有误，回静态修正
```
