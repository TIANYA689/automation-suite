# Emulated Execution Debug

目标：**不启动真实目标进程、不需要真机、不需要完整操作系统**，直接把一段机器码跑起来，拿到它的输入输出。

适用场景：算法片段复现、从被保护代码里"骗"出解密结果、跨架构片段执行、把静态分析结论变成可验证的运行结果。

不适用：需要完整内核/驱动语义、需要真实网络交互、需要图形或硬件外设的场景。

## 启动协议

1. **确定要模拟的最小范围**：一个函数、一个循环体、或一段字节码。范围越小，成功率越高。
2. **确定架构与调用约定**（见下方速查表），拿到代码起始地址、参数、栈与返回地址。
3. **优先原始字节加载**：不解析 ELF/PE/Mach-O 头，直接把目标字节映射进模拟内存。只有代码引用了特定地址段（跳转表、重定位、只读数据）时才做最小解析——且只映射需要的那几段。
4. **识别外部依赖**：列出这段代码会调用的 libc/JNI/syscall/C++ runtime 函数，逐个决定如何模拟。
5. **跑 → 读错误 → 补 → 再跑**，迭代到目标函数完整执行。
6. **落盘**：模拟脚本、环境桩定义、trace、输出数据、以及"哪些依赖被桩掉"的清单。

## 五条核心原则

1. **原始字节优先**：能裸跑就不解析格式，减少无关复杂度。
2. **显式识别上下文依赖**：不假设"没有外部调用"，先把调用点找出来。
3. **大量使用回调**：回调是本技能的主要工具——既用于模拟环境，也用于调试、trace 和错误恢复。
4. **迭代修复**：每次崩溃都是一条信息，用回调输出定位，而不是重写脚本。
5. **最小 trace 输出**：块级 trace 优先于指令级；指令级只在很小范围、很短窗口内开启，并加计数器。

## 环境模拟策略

| 类别 | 典型函数 | 模拟策略 |
|---|---|---|
| libc | malloc/free/memcpy/strlen/printf | 在回调里用宿主语言实现；malloc 用 bump allocator 即可 |
| JNI | GetStringUTFChars/FindClass/GetMethodID | 在模拟内存里建一张假 JNIEnv 函数表，每项写一个返回桩，然后 hook 桩地址 |
| syscall | read/write/mmap/ioctl | hook 中断事件，按系统调用号分发 |
| C++ runtime | operator new/__cxa_throw | hook 并模拟（异常可简化为"记录并返回"） |
| 库函数 | pthread_mutex_lock/dlopen | hook 后直接返回成功 |

**通用 hook 模式**：注册代码回调，当 PC 命中已知导入地址时，执行宿主语言实现的模拟逻辑，然后**把 PC 设为返回地址（LR）跳过原函数**。

## 回调类型对照

| 回调 | 用途 |
|---|---|
| 代码级 | 按地址拦截导入调用；指令级 trace（少用，窄范围） |
| 块级 | 块级 trace（优先于指令级） |
| 未映射内存 | 自动映射缺失页，从 unmapped 错误恢复 |
| 内存读/写 | 仅对目标数据范围 trace 访问 |
| 中断 | 拦截 SVC/INT 做系统调用模拟 |

## 架构与调用约定速查

| 架构 | 模拟器常量 | 模式 | 栈指针 | 返回地址 | 参数 | 返回值 | 系统调用 |
|---|---|---|---|---|---|---|---|
| ARM64 | ARM64 | 小端 | SP | X30 | X0–X7 | X0 | X8 + SVC #0 |
| ARM32 | ARM | THUMB/ARM | SP | LR | R0–R3 | R0 | R7 + SVC #0 |
| x86-64 | X86 | 64 位 | RSP | 栈上 | RDI,RSI,RDX,RCX,R8,R9 | RAX | RAX + syscall |
| x86-32 | X86 | 32 位 | ESP | 栈上 | 栈上 | EAX | EAX + int 0x80 |
| MIPS32 | MIPS | MIPS32 + 大端 | $sp | $ra | $a0–$a3 | $v0 | $v0 + syscall |

ARM32 的 THUMB 模式容易被忽略：地址最低位为 1 表示进入 THUMB，未设置会直接跑飞。

## 迭代调试循环

```text
Run
  → 读回调输出：哪个地址 fault、类型是 read / write / fetch
Diagnose
  → fetch 未映射        = 缺代码页，补映射
  → read/write 未映射   = 缺数据段，或指针未初始化
  → 命中导入桩          = 该调用还没实现，加模拟 hook
  → 死循环             = 加代码 hook 带执行计数，超阈值停
Fix
  → 只改一处，保持其余不变
Re-run
```

**验收**：目标函数在模拟中完整执行不崩，且输出与已知样本一致（有已知样本时）。

## 常见坑

| 坑 | 处理 |
|---|---|
| 忘记设置返回地址 | 函数执行到 ret 时跳到 0；显式写 LR/栈上返回地址为哨兵值 |
| 栈未分配 | 必须显式映射栈区并设置 SP，不能只映射代码段 |
| 字节序搞错 | MIPS 常见大端；ARM/x86 小端。写错会得到看似合理的垃圾数据 |
| 未初始化寄存器 | 某些代码假设调用者已清零寄存器；显式置 0 并记录该假设 |
| 高估可模拟范围 | 一旦出现"需要真实内核语义"的调用，停止扩展，改为桩掉或换真机验证 |
| 把模拟成功当成结论正确 | 模拟跑通只说明不崩；结论正确性必须用已知输入输出对验证 |

## 与静态分析的配合

模拟执行最适合用来**验证**静态结论，而不是替代它：

1. `binary-symbol-recovery` 给出"这个函数大概是 AES 解密"。
2. 本技能把密文喂进去，看输出是否为可读明文。
3. 输出合理 → 静态结论升级为高置信度。
4. 输出不合理 → 说明参数、密钥或范围有误，回到静态分析修正。
