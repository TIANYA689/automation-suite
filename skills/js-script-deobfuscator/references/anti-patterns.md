# 反模式与误判清单

遇到对应问题时读取；不需要为每个任务重复背诵。每条都给出"误判"与"应执行的检查"。

## 一、判定类误判

| 误判 | 应执行的检查 |
|---|---|
| 看到 HTTP 200 空内容就断定签名或环境错误 | 检查业务错误码、参数、权限、分页结束条件及同期成功样本 |
| 超时或 SSL 错误就断定指纹被识别 | 区分网络、代理、证书、协议与服务端故障，做受控对比 |
| 看到 `eval` 就断定是打包器 | 可能是正常业务代码或 VM 初始化 |
| 看到 `switch` 就断定控制流平坦化 | 必须同时看到状态变量在循环内更新、且分发依赖该变量 |
| 看到大数组就断定是 VM 字节码 | 可能只是普通查找表；需确认存在虚拟 PC 与分发循环 |
| 解码字符串全是单字母乱码就当成功 | 说明字符串是动态加密的，解码路径不对 |
| 一个样本签名对上就交付 | 必须用新输入回归，且要在无浏览器环境下验证 |

## 二、执行类误判

| 误判 | 应执行的检查 |
|---|---|
| 用过期 Cookie 硬编码支撑可持续采集 | 为鉴权/动态 Cookie 定义刷新来源、失败条件和恢复方式 |
| 拿浏览器验签通过证明协议程序可独立运行 | 用 Node 运行时或实际 Python 产物在无浏览器环境回归 |
| 样本为空、期望值缺失或字段名拼错仍当通过 | 验证输入结构，每个样本至少一个有效断言 |
| 已有同站项目却从零创建替代项目 | 先读需求工作区、基线和相关案例，再判断改版范围 |
| 沙箱跑通就认为还原正确 | 沙箱只证明解码基础设施能跑，业务语义需另验证 |
| 请求超时后无条件重放 POST | 无法证明幂等时停止并核对服务端结果 |

## 三、观测类误判

| 误判 | 应执行的检查 |
|---|---|
| Hook 已注册/待挂载就认定捕获成功 | 检查同一上下文与帧的追踪数据；未命中不构成未执行证据 |
| 源码改写成功就认定插桩运行 | 检查运行时标记与实际日志，再判断解析/执行失败 |
| 原生追踪没记录就认定没读取属性 | 核对固定点覆盖、事件容量、进程确认与快照语义 |
| 同 URL 多请求靠 URL 猜响应归属 | 使用请求对象关联；调用栈归因仍是启发式 |
| 停止捕获立即返回就认定所有响应完整 | 指定有界等待并检查待完成请求/响应与正文状态 |
| 将缓冲区截断当完整证据 | 检查丢弃计数、正文状态与两层截断字段 |
| 高频 Hook 不影响目标 | 所有 Hook/Proxy 都可能改变原生性与对象身份，需对照无 Hook 基线 |
| 反调试没触发就认为没有反调试 | 检测可能是条件性的，换环境或换时序才会触发 |

## 四、改写类误判

| 误判 | 应执行的检查 |
|---|---|
| AST 解析成功就认为改写完成 | 复杂语法（模板串、正则字面量、可选链、`super`、私有成员）可能被整段跳过，需检查跳过原因 |
| 多个样本通过就认为全程序等价 | 只说明这些样本一致，不是等价证明 |
| 改写后请求失败就归因于"环境检测" | 先按"原始输入 → 拼接 → 时间/随机值 → 中间值 → 最终签名"定位**首个偏差** |
| 把分析副本当等价代码交付 | 分析副本未验证等价，只能用于阅读 |
| 用正则做局部替换处理复杂语法 | 正则无法保留选择范围；应改用 AST |

## 五、默认失败处理顺序

```text
1. 回看已有证据与相关案例
2. 选择适合当前类型的观测手段（Hook / 插桩 / 环境复现）
3. 校验入口与输入输出边界
4. 按证据做最小环境调整
5. 记录未解决问题，如实交付
```

**不要**：用强制停顿代替诊断；盲目重放操作；在没有新证据时反复重试同一手法。

## 六、验收分层

| 层级 | 内容 | 是否可替代 |
|---|---|---|
| 离线样本回归 | 用固定输入验证解码/签名函数 | 不可替代真实请求验证 |
| 当前接口代表性请求 | 至少 5 次，覆盖成功与失败路径 | 不可替代长时间稳定性 |
| 长时间稳定性 | 按业务需要另行约定 | **未实际跑过不得写成通过** |

浏览器依赖是否允许以用户的交付要求为准；默认交付应保持无浏览器依赖。
