# 知识路由指南

## 决策顺序

先问“未来谁在什么时刻需要这条知识”，再决定文件类型。

| 知识类型 | 权威落点 | 典型内容 |
|---|---|---|
| 项目事实 | 项目 README/docs | API、目录、业务状态、部署约束 |
| 设计决策 | ADR/implementation plan | 选择、替代方案、后果 |
| 每次执行必须遵守 | SKILL.md | 核心步骤、安全门、检查点 |
| 仅特定情况需要 | references | 变体、长表、背景、模式库 |
| 重复机械操作 | scripts | 扫描、转换、验证、生成 |
| 固定交付骨架 | assets/templates | 报告、配置、视觉模板 |
| 独立可触发能力 | 新 Skill | 明确用户意图、完整工作流、独立维护 |
| 用户长期偏好/历史 | 运行时记忆机制 | 仅在明确请求且环境允许时 |

## 所有权规则

选择“执行责任”最强的资产作为权威来源：

- 路由知识归负责选择目标的 Skill；
- 语言实现知识归对应语言 Skill；
- 安全边界归实际执行危险动作的 Skill；
- 跨语言共同原则优先放在上层架构 Skill 或共享 reference；
- 其他 Skill 只写一句链接和适用条件。

## 新 Skill 门槛

同时满足以下条件才创建新 Skill：

1. 有独立且可描述的触发意图；
2. 现有 Skill 没有合理所有权；
3. 包含至少三步可复用工作流；
4. 能设计正向与负向触发样例；
5. 有明确输出和验证方式；
6. 未来维护者能够识别何时更新它。

若只满足“内容很多”，应使用 reference，不应创建新 Skill。

## 升级与降级

- 项目知识在第二个独立项目验证后，可升级为 Skill 候选。
- 全局规则若依赖已消失的版本或服务，应降级到历史记录或删除。
- 多处重复内容应收敛到一个权威来源。
- 未能复现的“最佳实践”降级为观察项，不继续强制执行。
