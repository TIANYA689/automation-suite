# Binary Symbol Recovery

目标：把"没有名字的二进制"变成"有名字、有结构、有调用关系的可读模型"，并且每条结论都带证据。

只做静态恢复。需要跑起来观察行为时转 `emulated-execution-debug`；需要处理 Python/JS 源码级包装时转对应解密技能。

## 启动协议

1. **盘点输入**：确认样本路径、大小、SHA-256、架构、位数、是否 stripped。记录到任务记录，不覆盖原文件。
2. **选择数据源**，按优先级：
   - 反编译导出目录（`decompile/` + `strings.txt` + `imports.txt` + `exports.txt`）：最省上下文，优先。
   - IDA/Ghidra 的 MCP 或脚本接口：可交互，适合迭代。
   - 原始二进制 + 反汇编器：兜底。
3. **建立基线**：先只读导入表、导出表、字符串表，形成"这个二进制大概在做什么"的第一印象，再进入函数级分析。
4. **声明分析范围**：一次只锁定 1~3 个函数或一个 struct 的调用簇，不要全量铺开。

## 导出目录契约（证据的物理定义）

若样本尚未导出，按下述结构产出，这是本技能所有后续步骤的输入约定：

```text
./
├── decompile/               # 每个函数一个文件，按十六进制地址命名：0x401000.c
├── decompile_failed.txt     # 反编译失败清单
├── decompile_skipped.txt    # 主动跳过清单（体积/超时/不支持）
├── strings.txt              # address, length, type, content
├── imports.txt              # address:function_name
├── exports.txt              # address:function_name
└── memory/                  # 内存 hexdump，按固定块切分
```

**函数文件必须自带调用图切片**，把关系写在函数头注释里：

```c
/*
 * func-name: sub_401000
 * func-address: 0x401000
 * callers: 0x402000, 0x403000
 * callees: 0x404000, 0x405000
 */
int __fastcall sub_401000(int a1, int a2) { ... }
```

这样后续无论是人工还是 Agent 定位，都不需要重新全量扫描。若导出工具不产出 callers/callees，先用交叉引用补齐再继续。

## 符号恢复三步法

### 第一步：内部特征

按证据强度从高到低：

1. **魔数与常量表**——一旦命中，基本可以直接命名，见 [算法常量指纹](references/algorithm-fingerprints.md)。
2. **字符串常量**——错误信息、路径、格式串、URL 往往直接泄露用途。
3. **代码结构**——循环形态、位运算密度、常量位移、查表模式。

### 第二步：交叉引用（本技能核心）

没有符号时，靠"成对调用"和"参数/返回值形态"反推：

| 模式 | 识别依据 |
|---|---|
| 分配/释放 | 取 size 返指针 ↔ 取同一指针 |
| 加锁/解锁 | 同一锁对象进出 |
| 打开/关闭 | path + flags 返 handle ↔ 取 handle |
| 线程创建/汇合 | 出参 + attr + func + arg ↔ tid + 出参 |
| socket 创建 | 固定常量调用形态，如 `(2, 1, 0)` 对应 AF_INET/SOCK_STREAM |
| connect/bind | 地址结构长度参数为固定 IPv4 长度 |
| 内存拷贝/置零 | 三参数 (dst, src, n) / (ptr, 0, 常量) |
| 字符串比较 | 返回值与 0 比较后分支 |

返回值模式同样有信息量：文件与 socket 出错返回 -1；分配失败返回 NULL；成功返回 0；某个长度结果被喂给拷贝函数的长度参数。

### 第三步：收集与检索

先本地推理（参数个数与类型、成对调用、调用链中的已知导入、与已知算法的结构相似度）；**只有在本地推理不足以定名时**才检索：搜魔数、搜代码模式、搜唯一字符串、搜参数形态。

## 结构体恢复

从内存访问模式重建布局：

1. 读目标函数，找指针参数（潜在 struct 指针）。
2. 采集访问模式并记录为 `offset / size / access(read|write) / type`：

```c
*(a1 + 0x10)              // 偏移 0x10
*(_DWORD *)(a1 + 8)       // 32 位
*(_QWORD *)(a1 + 0x20)    // 64 位
*(a1 + 8 * i)             // 数组，元素 8 字节
*(*a1 + 0x10)             // 嵌套：首字段是指针
```

3. 遍历 callers：看调用点传参形态（直接传指针 / 取地址 / 刚分配了多大一块），以及调用前后对该对象的操作。
4. 遍历 callees：看参数如何被使用，是否被转交给别的函数。
5. 聚合：按 offset 排序；**结构体大小 = 最大偏移 + 末字段大小**。

类型推断规则：

- 被当函数指针调用 → 函数指针
- 传给字符串函数 → 字符串指针
- 与常量比较 → 枚举/标志位
- 自增自减 → 计数/索引
- 偏移 0 是函数指针表 → 虚表（C++ 对象）
- next/prev 成对出现 → 链表节点
- 引用计数字段 → 引用计数对象

输出模板见 [结构体与符号报告模板](references/report-templates.md)。

## 置信度与验收

每条结论必须同时给出：**建议名称、置信度（高/中/低）、推理链、支撑证据位置**。

| 置信度 | 判据 |
|---|---|
| 高 | 命中算法常量表，或成对调用 + 参数形态双重吻合，或字符串直接点明用途 |
| 中 | 仅成对调用或仅参数形态吻合，无直接命名证据 |
| 低 | 仅代码结构相似，属于待验证假设 |

验收标准：

- 符号恢复：给出建议符号名 + 置信度 + 推理链；能识别已知算法则直接给结论。
- 结构体恢复：给出结构体定义 + 估算大小 + 置信度 + **每个字段一行访问证据**。

不允许只给名称不给证据；不允许把"低置信度"写成确定结论。

## 失败处理

| 情况 | 处理 |
|---|---|
| 反编译失败或跳过 | 读 `decompile_failed.txt`，改用反汇编 + 人工读关键基本块，不放弃该函数 |
| 无交叉引用信息 | 退回调用链上下文（谁调用了它、它调用了谁），或从字符串引用反查 |
| 结构体大小无法收敛 | 检查是否有间接索引（`base + index * size`），改按数组元素建模 |
| 疑似 C++ 对象 | 先找构造/析构/虚表写入点，再谈字段语义 |
| 大函数（数千行） | 按基本块切分，只分析被外部引用最多的块 |
| 无法定名 | 如实标注"低置信度待验证"，写清还需要什么证据，不编造名称 |
