# 分析报告模板

本模板是 `apk-reverse-analysis` 的交付契约。**没有按这个结构写的报告不算交付。**

## 面向委托方的报告

```text
样本：        <文件名> <sha256>
包名 / 版本： <package> <versionName> (<versionCode>)
目标 ABI：    <arm64-v8a / armeabi-v7a / …>   来源：<活进程映射，非属性查询>
基线：        <零改动重签名构建的 sha256>   结果：<安装 / 启动 / 稳定>

结构审计
  结构差异：  <逐文件结果>
  验证器：    <条件分支 → move-result 的违规数，改动前后>
  改动审计：  Tier1=<n>  Tier2=<n>  缺失集合=<空 / 非空>
  未改动部分：<与原件逐字节一致的结论>

加固识别
  壳：        <无 / 族名>          证据：<application name、库名、assets 特征>
  虚拟化：    <无 / 是>            证据：<tell 编号 + 命中位置>
  方法体清空：<比例>  对照基线：<比例>   结论：<高比例确认 / 低比例不构成排除>
  运行时：    <字节码 / Flutter / Unity / RN / 原生>   证据：<特征文件>

原生层
  JNI 形态：  <静态链接 / 动态注册 / 回调>   证据：<导出符号计数>
  加载行为：  <实际映射的库清单，来源=活进程>
  分析边界：  <做到了哪一步、在哪一步停>

协议与归属
  传输：      <REST / gRPC / QUIC>        解码：<往返一致率>
  归属判定：  <客户端拥有 / 服务端权威 / 不确定>   依据：<归属矩阵命中行>
  判定结论：  <这个限制能不能在客户端侧达成>

到达级别：    0..7（口径见 kb/methodology/techniques/03-verification-ladder.md）
```

## 面向最终用户的说明

只放中性的机械信息，**不要写机制、改动点与推理**：

- 名称与版本
- 安装前提（签名冲突警告：签名者不同意味着旧安装必须先卸载）
- 校验和
- 一行范围与免责声明

## 残留怎么写

**残留是报告里最有价值的一段**，不是免责声明。判据：

- 写**机制**，不写"没搞定"。"X 仍然存在，因为它随界面的主数据载荷一起下发，
  在传输层抑制它会把整个界面带崩"是有用的；"部分功能仍受限"不是。
- 写**为什么停**：是成本判定的结果，还是证据不足。
- 写**还缺什么**：缺样本、缺设备、缺某个不分发的依赖。

## 强度标签怎么用

| 场景 | 档位 |
|---|---|
| 跑过命令、输出已落盘 | `observed` |
| 由已记录的机制推出，这一步没执行 | `inferred` |
| 假设的、转述的、本仓库没复现 | `unverified` |

**禁止**：整篇报告一个档位；把"机制蕴含它"写成 `observed`；
把 `unverified` 的结论放进结论段而不放进未验证段。

## 证据文件约定

- 所有产物落在 `exports/` 下，**不要写进技能目录**。
- 证据文件里保留命令原文与输出原文，不要只留结论。
- **发布出去的文档永不引用敏感命中值**，只留规则、类别、强度、位置、计数。
- 原始样本不改、不覆盖；改动前先备份。
